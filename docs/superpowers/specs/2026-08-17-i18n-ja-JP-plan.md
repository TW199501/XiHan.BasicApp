# ja-JP 日文語言包 — 設計與實作計劃

> 階段 1 of 4。後續：ko-KR → de-DE → zh-TW 補完。
> 本文以繁體中文撰寫（工作文件，非產品文檔）。

## 1. 目標

讓 `ja-JP` 成為一個**完整可用**的介面語言：使用者切到日文後，外殼、業務頁面與五個可選模組全部顯示自然的日文，不出現英文或中文殘留。

翻譯來源是 `en-US`（使用者已人工對照過 `zh-CN` 與 `en-US`，故英文稿可信）；語意不明處回查同鍵的 `zh-CN` 確認原意。

## 3. 範圍邊界

**做**：前端 `ja-JP` 的全部文案 + 讓它能被選用的最小程式接線。

**不做**（已與使用者確認）：

- **後端完全不動**。`Localization/` 維持 `zh-CN`/`en-US`。前端送 `X-Language: ja-JP` 時，後端回退到 `DefaultCulture`（`zh-CN`），因此**列舉標籤與 API 錯誤訊息在日文介面下仍是簡體中文**——這是本階段的已知限制，不在此處理。
- 不建立「已啟用語言」的閘門機制。四個語言最終都會翻完，多一層清單只是維護負擔。
- 不重構成集中式語言註冊表。本階段只擴充必要的幾處；若之後覺得散，再單獨處理。

## 6. 翻譯準則

### 6.1 不可動的東西

- **鍵名、巢狀結構、檔案內順序完全不變**。`validate-i18n.mjs` 要求各語言鍵集完全對稱，動結構就是紅燈。
- **佔位符原樣保留**：`{tenant}`、`{count}`、`{name}` 等，以及 vue-i18n 的 `@:` 連結語法。
- **不翻譯的詞**：專有名詞與技術識別字（SignalR、OAuth、Token、API、JSON、Cron、Webhook）、權限碼、程式識別字。

### 6.2 術語表（先定，全程一致）

| 中／英 | 日文 | 中／英 | 日文 |
| --- | --- | --- | --- |
| 用戶 / User | ユーザー | 審批 / Approval | 承認 |
| 角色 / Role | ロール | 審計日誌 / Audit Log | 監査ログ |
| 權限 / Permission | 権限 | 登入 / Login | ログイン |
| 選單 / Menu | メニュー | 儀表板 / Dashboard | ダッシュボード |
| 租戶 / Tenant | テナント | 匯出 / Export | エクスポート |
| 部門 / Department | 部門 | 匯入 / Import | インポート |
| 字典 / Dictionary | 辞書 | 定時任務 / Scheduled Job | スケジュールジョブ |

例：`approval.review.page_name` 由 `'Approval Center'` → `'承認センター'`。

### 6.3 文體

- **按鈕、欄位標題、選單項、標籤** → 体言止め（名詞結尾），不加「です・ます」。例：`保存` `削除` `ユーザー管理`
- **提示、確認、錯誤、成功訊息** → です・ます体。例：`保存しました` `削除してもよろしいですか`
- **輸入框 placeholder** → 「〜を入力してください」／「〜を選択してください」

### 6.4 長度

日文通常短於英文、略長於中文。表格欄位標題盡量壓在 6 字以內，避免撐破既有欄寬——`identity.ts` 與 `log.ts` 的列表欄位最需注意。

## 8. 驗證

```bash
cd frontend
pnpm type-check     # vue-tsc
pnpm validate       # i18n 鍵集對稱 + 孤兒鍵 + 模組目錄門禁
pnpm check          # type-check + lint + validate
pnpm build
```

`pnpm validate` 是本計劃最關鍵的自動化保護：它會抓出 `ja-JP` 與其他語言的鍵集不對稱，以及引用了但沒定義的孤兒鍵——後者 type-check 與 eslint 都抓不到，運行期只會顯示裸鍵名。

人工抽查清單：登入頁、用戶管理、承認センター、偏好設定、操作日誌、聊天、工作流。重點看排版是否被文字長度撐破。
